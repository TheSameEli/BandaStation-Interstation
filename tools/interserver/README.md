# Межстанционный шаттл: локальный Windows-прототип

Модификация **TheSameEli**, <https://www.twitch.tv/thesameeli>.
Авторство и лицензии: [NOTICE-INTERSTATION.md](../../NOTICE-INTERSTATION.md).

Два самостоятельных игровых процесса Bandstation: Кибериада и Метастейшен.
Каждый ведёт свой раунд. Передача пассажира и багажа идёт напрямую подписанными
BYOND Topic-запросами, без приложения-моста. Обоим процессам нужны одинаковые
DMB, BYOND и протокол. Без включённой конфигурации модуль не интегрируется в игру.

## Статус и ограничения

- Контролируемый тест на Windows, BYOND **516.1685**. Адреса ограничены
  `127.0.0.1`; публичная/удалённая эксплуатация не реализована.
- Один логический шаттл, номера операций, журнал владения, передача частей
  снимка, проверки версии, раунда и подписей. Не более восьми пассажиров,
  500 предметов, 2 МиБ Base64 и 24 рейсов на тестовую пару раундов.
- Локальный запуск **явно включает диагностический режим**: каталог предметов
  расширен до типов текущего билда. Переносимые значения и прямые связи с
  дочерними предметами восстанавливаются; локальные ссылки и внутреннее
  состояние компонентов могут отличаться или отсутствовать. Отклонения
  записываются как `INTERSERVER DEVIATION`. Это не полная сериализация SS13.
- Основа восстановления — живой обычный человек, его внешность/DNA, mind,
  исходная профессия, инвентарь и кресло. Личности и воспоминания восстанавливаются
  по местным типам; нейрочипы — через метаданные и связь с мозгом, импланты —
  через `implant()`. Сложные эффекты, quirks, химия, болезни, изменённая анатомия,
  антагонистические цели и ссылки на исходный раунд не имеют полной поддержки.
  Невосстановимые случаи могут остановить рейс.
- В диагностическом режиме суммы счёта, долг и баллы следуют за персонажем;
  оставленный счёт блокируется, на другой стороне используется местный счёт.
  Номера могут различаться. Истории операций и банковские задания не объединяются.
- Гостевой вход допускается только в локальном диагностическом тесте; ключ
  и идентификатор компьютера сверяются с разрешением исходной стороны.
  Обычный режим требует учётную запись BYOND.
- Полного восстановления после холодного перезапуска **нет**. Перезапуск одной
  стороны блокирует старый перенос и помещает участников в карантин. Запуск
  после остановки обеих создаёт **новую пару раундов**, сохраняя старые журналы.
- Производные тестовые карты заменяют arrivals-порт и поздний вход. Оригинальные
  карты не меняются. Диспетчеризация обычных прибытий/доков — отдельный будущий этап.

## Сборка

Сначала выполните штатные [инструкции сборки](../build/README.md) и подготовьте
нативные зависимости согласно `dependencies.sh`. Дополнительно нужны PowerShell 7,
Python с `bidict` и Zig 0.14.1. Все команды выполняются из корня репозитория.
Укажите пути к своим инструментам; локальная папка `../toolchain` не входит в Git.

```powershell
$ByondBin = 'C:/tools/byond/bin'   # BYOND 516.1685
$NativeDir = 'C:/tools/bandstation-native'
$Zig = 'C:/tools/zig/zig.exe'
# NativeDir: rust_g.dll, rust_utils.dll и dreamluau.dll штатных версий билда
./tools/interserver/build_native.ps1 -Zig $Zig -OutputDirectory $NativeDir
python tools/interserver/create_test_maps.py
$env:DM_EXE = Join-Path $ByondBin 'dm.exe'
bun tools/build/build.ts tgui
bun tools/build/build.ts dm
```

`transit_crypto.dll` работает внутри игрового процесса: Windows CNG HMAC,
проверка подписи, FlushFileBuffers и атомарная публикация неизменяемого файла
без перезаписи. Это не отдельный сервис.

## Запуск и остановка

```powershell
$ServerRoot = 'C:/ss13/interstation-local'
./tools/interserver/start_local.ps1 -ByondBin $ByondBin -NativeDirectory $NativeDir -ServerRoot $ServerRoot
./tools/interserver/create_shortcuts.ps1 -ByondBin $ByondBin -NativeDirectory $NativeDir -ServerRoot $ServerRoot
```

Создаются четыре ярлыка: сервер и клиент для каждой станции. Повторный запуск
ярлыка не создаёт второй процесс. A — Кибериада, `byond://127.0.0.1:1337`;
B — Метастейшен, `byond://127.0.0.1:1338`. Шаттл первоначально на A.
Предупреждение и полёт в локальном профиле — по пять секунд; согласование
состояния требует дополнительного времени. Интерфейс и объявления используют
названия станций, прибытие указывает станции отправления и назначения.
Бандлы интерфейса копируются отдельно каждому экземпляру вместе с DMB.

Для обновления останавливайте обе стороны до запуска новой сборки:

```powershell
./tools/interserver/stop_local.ps1 -ServerRoot $ServerRoot
```

Это завершает текущие тестовые раунды, а не сохраняет персонажей для холодного
рестарта. Проверка PID/пути/времени старта защищает посторонние процессы.

## Проверка и конфигурация

[Ручные сценарии и результаты](MANUAL_TESTING.ru.md).
Одноразовая диагностика без запуска рейса:

```powershell
python tools/interserver/inspect_pair.py $ServerRoot
```

`inspect_pair.py` — административная утилита, не постоянный мост. Её `--call`
вызывает рейс и предназначен для контролируемого пустого шаттла.
Исторические протокольные тесты: `run_tests.ps1`. Игровые проверки кодеков
требуют отдельной сборки с `-DUNIT_TESTS -DTRANSIT_PROFILE_TEST`; перед запуском
пользовательских серверов пересоберите игру **без** этих определений.
Они не заменяют ручную проверку клиента и не доказывают сохранение всех состояний.

`config.example.json` — отключённый пример. Локальный launcher создаёт ID пары,
случайный общий секрет, адреса и названия станций, включает диагностический
профиль. Полный набор полей см. в `start_local.ps1`.

**Не публикуйте** `pair.json`, архивы пар, рабочий `interserver_transit.json`,
логи, снимки персонажей, ключи и данные учётных записей. В форке оставлен только
пример с заглушкой секрета; локальные игровые данные и бинарные результаты сборки
модификации не входят в исходники публикации.
